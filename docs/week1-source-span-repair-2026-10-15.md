## v12 来源范围协议（历史记录）

v12 将来源范围明确改为“当前 batch 全局 ID 闭区间”，允许跨消息和 extraction chunk，并同步修改提示词与对应的原文拆分映射。它保留 v10 的单层单位、v11 的 ISO 形状约束及既有一层主辅结构；模型、完整历史、输出上限和实际时间解析规则不变。独立实现复核、完整回归及请求上下文检查通过后启动真实运行；该运行随后因 LongMemEval 抽取输出截断退出，最终状态见下文。

抽取模型只接收当前 `new_chunks` 全文及角色、时间、source_order；不发送旧批次文本。未能从当前批次解析的指代保留原表述，不从不可用上下文补写身份或事实。各批次仍覆盖完整合法历史。

程序预先标记当前原文中的有限片段，模型用展示的整数 ID 指定连续来源范围：

```json
{"source_unit_ranges": [{"first": 0, "last": 0}]}
```

每个 chunk 的 `source_units` 是紧凑的 `[id, exact_text]` 列表，所有 ID 都绑定原文的确定字符范围。仅使用现有 NLTK `WordPunctTokenizer` 生成的单层词和标点片段，没有重叠的句/分句候选。同一 chunk 内的片段按原文顺序排列且互不重叠，当前批次内用稠密整数 ID 按展示的 chunk 顺序连续分配，不重置、不留洞。结构化输出将 `first`、`last` 分别限定为 `0..N-1` 内的整数，每个允许 ID 都对应真实候选；本地仍严格拒绝布尔、字符串、浮点及越界 ID。模型只复制展示编号，不计算字符坐标；无需新依赖或额外模型调用。候选数量与原文长度线性相关，不枚举全部连续词组合。

每个 `{first, last}` 明确选中 `first <= id <= last` 的全部单位，两端可以位于当前 batch 的不同 chunk 或消息。编号顺序是展示顺序，不是跨消息共用的字符偏移。程序按每个相交 chunk 分别生成精确原文片段：从该 chunk 首个被选单位开头到末个被选单位结尾，包含其中的文字、标点、空白和换行；不将不同消息拼成一段伪造引文。中间 chunk 的全部区间单位都是本协议显式选入的证据，不是程序暗中扩大范围。单个单位仍用相同的 first、last ID 表示。

普通事实用连续词范围覆盖最小自足分句；全局偏好与项目内容混合时仍应使用较窄的范围或多个不连续范围，排除无关内容。重复的 `Paris` 各有不同的词片段 ID，因此仍能用单点范围只定位第二处。跨 chunk 的连续长消息和跨消息证据可以用一个全局范围选择；不希望选入中间文字时应使用多个范围。不同 extraction chunk 可能覆盖原消息的重叠部分，保留各自原始字符定位，不将 chunk 展示顺序误称为全局无重叠字符顺序。

程序将全局范围拆为各 chunk 的原文片段，再将同 chunk 中重叠或仅隔空白的选中范围合并。单个全局范围内部的单位是模型显式选入的完整闭区间；不同范围之间未选中的实质字符不会被补入。引文及 occurrence 均由程序计算，再交给原 engine 的二次严格校验。未知 ID、重复 first/last 对、倒序端点、空来源，以及不能按既有非重叠 occurrence 表达的范围，仍使整次抽取失败；不交换端点、不启发式缩小或补写范围、不模糊匹配、不修补事实、不丢弃单条事实、不增加内容重试。不兼容旧 `source_unit_ids` 列表等 wire，不提高 4096 输出 token 上限。日期上下文判断需要覆盖拆分后全部被引用 chunk，而非只检查首端点。

外部 Add/Search 接口、数据库事实来源和 engine 的二次严格校验不变。来源映射模块已加入索引指纹；新协议从空索引重建当前方法，不打开旧版本索引。有限 ID 范围消除了模型复制引文和计算位置的任务，并压缩连续来源的输出；仍不能证明任意事实与所选来源之间的语义支持，也不能保证无界数组永不发生生成退化，需以真实首批验证与证据检查判断。

v8 已实现的一层主辅嵌套保持不变：每个主条目包含 `secondary_entries` 数组（可为空），辅助条目分别提供自己的内容、来源和元数据，不能继续包含辅助条目。模型不再输出 `parent_index`；程序按主条目及其辅助条目的顺序展平，为主条目设 null，为辅助条目计算主条目在展平列表中的位置。这样保留原有主辅机制，并从输出结构上排除环及辅助链；错误辅助条目仍使整次输出失败，不丢弃或继承缺失字段。v12 改变来源范围的明示含义与映射，不改变主辅展平及原有日历、时间和精度校验。

### 沿用 v11 的时间生成约束

从既有 `_DATE` 正则直接派生 `ISO_TIME_PATTERN`，只将 Python 命名捕获组改为非捕获组，避免另写一套日期语法。provider 为 `occurred_start`、`occurred_end`、`mentioned_at` 的字符串分支加入该 pattern，JSON null 仍可使用；主条目与辅助条目共用这些约束。`occurred_precision` 仍使用原有枚举。

该 pattern 控制 ISO 字符串形状，拒绝已复现的末尾 `Z.`；不代替真实日期、时间范围、精度配套和来源支持校验。`_parse`、`time_bounds`、`validate_temporal`、`event_overlaps` 与 v10 冻结版本的 AST 一致；非法日历日期、缺少精度及倒置范围仍由原解析器拒绝，不修剪句点、不改写模型值、不将错误条目丢弃。独立本地 ECMAScript RegExp 编译及合法/非法形状检查已通过，没有使用真实模型调用。
