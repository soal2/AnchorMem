# 通用 topic 与可选上下文

本文件记录 2026-10-11 已确认并落实的分类结构、模型分工及适用范围。项目上下文与查询时间范围均为可选项；系统规范化缺省值，项目内默认检索全局记忆与当前项目记忆，无项目时仅检索全局记忆。

## 通用类别

一级类别按记忆内容性质划分，具体业务领域作为内容标签，不继续扩充一级类别。

| topic | 代码标识 | 内容 |
|---|---|---|
| 用户档案 | `profile` | 用户本人的身份、背景和当前状态 |
| 偏好 | `preferences` | 用户全局适用的倾向性选择 |
| 实体知识 | `entities` | 相关人物、组织、项目等对象的信息 |
| 事件与安排 | `events` | 已发生事件、未来计划、承诺、变更、进展和结果 |
| 要求 | `requirements` | 用户明确提出、需要在指定范围内遵守的处理条件 |
| 方法与经验 | `methods` | 可复用的处理流程、解决方法、失败教训及其适用条件 |

用户档案、偏好默认全局。在项目中产生的其他类别默认归当前项目，明确跨项目共享时归全局；无项目时的普通条目归全局。方法与经验保留来源、适用条件和来源声明的验证情况，不把推测当作验证结果。

## 条目与目录

- 分类对象为独立记忆条目，原文完整保留。
- 采用“一主多辅”：每条记忆归一个主 topic，涉及其他 topic 的内容拆成条目分别保存。
- 辅助条目各自归属一个主 topic，可以独立检索，同时保留主辅关系和原文来源。
- “事件与安排”的下层目录按事项组织，同一事项的计划、变更、进展和结果关联保存。
- 每条事件记录保留时间和状态；时间范围查询使用时间字段筛选。
- 时间序列判断使用发生或生效时间，写入时间用于管理。
- 逻辑目录按“作用域 → topic → 事项”组织，仅事件与安排具有事项层。物理目录独立保存完整原始消息，向量和来源关系保存在 SQLite。
- 每条记忆引用可校验的原文片段及位置；片段作为 BM25 和原文向量索引单元，混合作用域的原文不整块进入检索。
- Jev 确认同一事项的新侧面时，建立独立归纳并继承事项标识；新事项创建新标识，不确定时独立保留，同名不直接归并。

## 模型分工

- 生成模型在已有抽取调用中，一并输出记忆条目、主 topic、主辅关系、作用域、来源片段和时间信息。
- 不再为写入分类单独增加 Jev 调用。
- Jev 继续负责增量归纳中的关系判断，以及查询时的相关 topic / 目录选择。
- 检索命中后回溯原文，原文证据交给上层生成模型作答。
- 归纳候选限于同用户、同作用域、同 topic，最多 5 条；同批暂存结果也参与匹配。未确定作用域的条目不参加归纳。
- 查询先限定作用域和时间，再统计有效向量数；超过 300,000 阈值才由 Jev 判断六个固定主题描述，不逐层递归判断。沿用 20 个种子和 16,000 token 证据预算。

## 项目范围

- Add、Search 的 `project_id` 可省略；省略、`null`、空白字符串均规范化为无项目。非空字符串去除首尾空白；无法解释的值报参数错误。
- 项目标识存在时由调用方明确传入，模型不从对话中推断标识，也不继承会话最近使用的项目。
- “全局”指同一用户的跨项目范围，用户之间仍保持隔离。
- 项目与会话分别标识，同一项目可以跨多个会话，一个会话也可以涉及多个项目。
- 在项目中产生的实体知识、事件与安排、方法与经验，默认归当前项目；用户明确指定跨项目共享时再设为全局。
- 查询指定项目时，默认检索“全局记忆＋当前项目记忆”。
- 先限定用户和项目适用范围，再由 Jev 选择相关 topic / 目录，并在选定范围内检索。
- 其他项目的项目级记忆不参与默认检索。
- 规范化之后计算请求指纹：省略与显式 `null` 等价；同一请求 ID 改变项目或内容仍报幂等冲突。

## 可选时间范围

- Search 接受可选 `event_time_range`，其中 `start`、`end` 均可省略或为 `null`；整个范围未传、为 `null` 或两端为空时不筛选。
- 只传一端表示单边开放范围；双边使用左闭右开 `[start, end)`。非法时间、逆序或无法相互比较的边界报参数错误。
- 按条目的发生或生效区间与查询区间相交筛选，不自动解析查询文本中的时间。
- 时间未知或时区无法与查询比较的记录不进入显式时间筛选；不为日期擅自补时区，不以写入时间代替事件时间。
- 所有召回、归纳来源回溯和邻居恢复遵守同一作用域及时间边界，越过排除片段时拆开证据窗口。

## 要求优先级

- 在当前项目内，项目级要求优先于与其冲突的全局要求，作为该项目的局部例外。
- 全局要求继续在其他项目生效，原始记录保留。
- Search 证据附 `entry_ids`、`topic`、`scope`、`project_id`、`requirement_priority`。要求优先级为项目要求 `2`、全局要求 `1`，其他条目为空；不单独调用模型判断覆盖关系。
- 回答模型接收原文及元数据，固定策略为“项目要求优先于冲突的全局要求，非冲突要求并存”。Search 本身继续只提供证据。

## 作用域未确定与失败处理

- 未提供项目标识而原文明确属于项目时，该条目保存为 `unresolved`，不自动提升为全局。普通条目照常保存，Add 返回 `unresolved_entry_count` 和 `warnings`。
- 未确定条目不参与默认检索及归纳，也不会自动归属后续项目；调用方可携带明确项目通过新请求重新写入原文。
- Add 保持同步、幂等及原子提交。模型、向量或来源校验失败时整批回滚，不提交半成品。

## 索引与评测

- 新索引使用 schema 5，指纹包含抽取结构、六类主题、作用域和检索规则。旧 schema 明确拒绝加载，必须从原文重建，不执行迁移。
- `configs/service/vikingjev.yaml` 使用独立的 `data/vikingjev-generic-topics-v5` 数据库及新的配置快照目录，历史实验产物保留。
- 五个 benchmark 的适配器为同一数据集、历史分组传入稳定项目标识，并统一向回答模型提供证据元数据。本次调整不重复运行既有 benchmark；历史结果不能当作本次源码的新实验结果。
- 继续记录供应商实际调用费用和阶段耗时；费用缺失值为空。不把 token 数量或幂等跳过当作费用和提速结论。
