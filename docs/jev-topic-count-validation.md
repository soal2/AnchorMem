# 固定记忆体量，改变主题数量

固定同一 SQLite 数据库、4096 个底层目录、81920 条 1024 维向量及三个查询。64 个细粒度项目主题依次合并成 4/8/16/32/64 个上层主题。记忆总量、底层内容、查询向量均不变；分组及对应摘要按粒度改变。每个题目/主题数量只调用一次真实 Jev，不重跑；本地全量/局部检索预热后交错各测七次。

本实验没有 GPT 生成摘要。摘要为固定模板，比较仅包含 Jev 判断和本地向量读取、点积、排序。生成摘要成本、自动分类成本、写入费用与真实问答准确率均不在本实验范围。

## 结论与限制

- 全量向量检索不使用主题分组，因此速度基本不变；本实验没有外部模型调用费用，本地计算仍有资源成本。
- 主题越细，定向查询所需向量越少。但超过每批十主题后，串行 API 次数增加；即使同一批内，更多判断题和摘要包装也会改变供应商费用。
- 全主题问题必须检索全部向量，增加主题只会增加控制开销。15 个合成案例均覆盖所有预设相关项目，但显式项目编号问题不能代表真实跨主题查询质量。
- 每组合只测一次 API，不能由 4 与 8 主题的时间差断言 8 是最优；第一次调用也受连接初始化影响。未验证更多主题在本地部署下的表现。
